<interfaces>
<!-- The kernel's spinlock protocol (from src/frame/lock.rs): -->

AtomicBool CAS with Acquire on success, Relaxed on failure:
  compare_exchange_weak(false, true, Ordering::Acquire, Ordering::Relaxed)
Release on drop:
  store(false, Ordering::Release)
Data access: via UnsafeCell only while locked (Deref/DerefMut on LockGuard)

<!-- The IPC rendezvous protocol (from src/communication.rs): -->

send(field, message):
  1. Check for waiting receiver: field.pop_waiter()
     - If waiter exists: return WokeReceiver(observer, message) — bypass queue
     - If no waiter: field.enqueue(message) — into FIFO queue
  2. Sender never blocks

receive(field, receiver):
  1. Check queue: field.dequeue()
     - If message available: return Received(message)
     - If empty: field.add_waiter(receiver) — link into waiters list
  2. Return Blocked

The protocol property: every sent message is either enqueued (dequeued later by
a receiver) or delivered directly to a waiting receiver. No message is lost or
duplicated.
</interfaces>

**Spinlock model** (`src/concurrency_models/spinlock.rs`):

Model the Lock<T> protocol from frame/lock.rs using loom primitives. This is an
ABSTRACT model — it does not import or test the actual Lock<T> type.

```
use loom::sync::atomic::{AtomicBool, Ordering};
use loom::sync::Arc;
use loom::thread;
```

Create a `ModelLock<T>` struct:
- `locked: AtomicBool` (same as kernel Lock)
- `data: loom::sync::atomic::AtomicUsize` (simpler than UnsafeCell for Loom — tracks the
  protected value as an atomic so Loom can see the accesses)

Acquire: spin on `compare_exchange_weak(false, true, Acquire, Relaxed)` using
`loom::thread::yield_now()` in the spin loop (Loom requires yield, not spin_loop hint).
Release: `store(false, Release)`.

Write these `#[test]` functions:

1. `loom_spinlock_mutual_exclusion`: Two threads each acquire the lock, increment
   a shared AtomicUsize (inside the "critical section"), and release. Each does
   N=2 iterations (keep small for Loom state space). Assert final value = 4.
   The property: no increment is lost, which proves mutual exclusion.

2. `loom_spinlock_no_concurrent_holders`: Two threads acquire the lock. On
   acquire, atomically set a "holder count" AtomicUsize from 0 to 1 (assert it
   was 0 — no other holder). On release, set back to 0. This directly asserts
   mutual exclusion: Loom will find any interleaving where two threads hold
   simultaneously.

Each test is wrapped in `loom::model(|| { ... })`.

**IPC rendezvous model** (`src/concurrency_models/ipc_rendezvous.rs`):

Model the send/receive rendezvous protocol from communication.rs. This captures
the ALGORITHM: "send checks for waiter first, then enqueues; receive checks
queue first, then blocks."

The model's shared state (inside Arc):
- `queue: loom::sync::Mutex<VecDeque<u64>>` — models the Field's message queue
- `waiter: AtomicBool` — models whether a receiver is waiting (simplified from
  the kernel's intrusive linked list to a boolean flag — captures the protocol)
- `waiter_woken: AtomicBool` — signals that the sender woke the blocked receiver
- `direct_delivery: loom::sync::Mutex<Option<u64>>` — models the direct-delivery
  path (WokeReceiver)

Model functions (not methods on a struct, matching the kernel's free-function style):

`model_send(field, value)`:
1. If `waiter.load(Acquire)` is true:
   - Set waiter to false (pop the waiter)
   - Store value in `direct_delivery`
   - Set `waiter_woken` to true (Release)
   - Return "WokeReceiver"
2. Else: push value into `queue`
   - Return "Enqueued"

`model_receive(field) -> u64`:
1. Try `queue.lock().pop_front()`
   - If Some(msg): return msg
2. Else: set `waiter` to true (Release)
   - Spin on `waiter_woken.load(Acquire)` with `loom::thread::yield_now()`
   - Read from `direct_delivery`
   - Return the value

Write these `#[test]` functions:

1. `loom_ipc_send_then_receive`: Spawn sender thread that sends value 42. Spawn
   receiver thread that receives. Use a loom barrier or sequencing to ensure
   send runs first (or let Loom explore both orderings). Assert receiver gets 42.

2. `loom_ipc_receive_then_send`: Same but the interesting case — receiver blocks,
   sender wakes. Loom explores the interleaving where the receiver's waiter=true
   store happens before the sender's waiter.load check. Assert value delivered.

3. `loom_ipc_two_senders_one_receiver`: Two senders each send a distinct value.
   Receiver dequeues both (may need two receive calls). Assert both values
   received (order may vary). This verifies no message loss under concurrent
   sends.

All tests wrapped in `loom::model(|| { ... })`.

IMPORTANT: Keep iteration counts small (2-3 per thread) — Loom explores
combinatorial interleavings, so even N=2 can produce millions of states.
Use `loom::thread::yield_now()` in spin loops, not `core::hint::spin_loop()`.
