<interfaces>
<!-- The kernel's scheduler queue protocol (from time_manager/earliest_eligible_virtual_deadline.rs): -->

Queue structure: flat array [Option<EevdfEntry>; 64] with count and swap-remove.

enqueue(observer):
  1. Check for duplicate (linear scan) — skip if already present
  2. Check capacity (count < MAX_QUEUE_DEPTH) — skip if full
  3. Insert at entries[count], increment count, add to total_weight

dequeue(observer):
  1. Find index via linear scan
  2. Swap-remove: move entries[last] into entries[idx], clear entries[last]
  3. Decrement count, subtract from total_weight
  4. Invalidate/fixup "current" index if it pointed to removed or swapped entry

pick_next():
  1. Scan for eligible entry (VET <= global_virtual_time) with earliest VD
  2. Fallback: if none eligible, pick earliest VD overall (prevents starvation)

The concurrency property: D53 says enqueue/dequeue are called while holding
Arena<Observer> lock, but pick_next/should_switch_to/on_preempt are called
WITHOUT locks. The model should verify that a lock-protected enqueue/dequeue
interleaved with a concurrent pick_next does not corrupt the queue.

<!-- The Observer lifecycle state machine (from src/observer.rs): -->

PrimaryState: Inert, Runnable, Blocked, Faulted
Orthogonal flag: suspended (bool)

Valid transitions:
  resume(): Inert|Faulted -> Runnable (clears suspended)
            Runnable+suspended|Blocked+suspended -> clears suspended
  suspend(): any state -> suspended=true
  block(wait): Runnable -> Blocked
  unblock(): Blocked -> Runnable (returns !suspended for enqueue decision)
  fault(): Runnable -> Faulted

The concurrency property: multiple cores may try to suspend/resume/unblock
the same Observer concurrently (e.g., IPC wakeup on core A while suspend
syscall on core B). Under the kernel's lock discipline (Arena<Observer> lock),
these are serialized — the model verifies the serialization produces valid
final states.
</interfaces>

**Scheduler queue model** (`src/concurrency_models/scheduler_queue.rs`):

Model the EEVDF queue's structural operations. The model does NOT replicate
virtual time arithmetic — it models the concurrent data structure operations
(enqueue, dequeue, pick_next) that could race under multi-core access.

The model's shared state:
- `queue: loom::sync::Mutex<ModelQueue>` — models the Arena<Observer> lock
  protecting enqueue/dequeue
- `ModelQueue`: a simplified flat array of `Option<u32>` (entry IDs instead of
  Observer pointers), with `count: usize` and swap-remove logic matching the
  kernel's implementation

```rust
struct ModelQueue {
    entries: [Option<u32>; 8],  // Small for Loom state space
    count: usize,
}
```

Model methods on ModelQueue:
- `enqueue(id)`: check duplicate, check capacity, insert at entries[count], count += 1
- `dequeue(id)`: find index, swap-remove (move last into gap), count -= 1
- `pick_next() -> Option<u32>`: scan entries[0..count], return first Some value
- `contains(id) -> bool`: linear scan
- `len() -> usize`: return count

**Observer lifecycle model** (`src/concurrency_models/observer_lifecycle.rs`):

Model the Observer's five-state machine with the `suspended` overlay. The model
captures the state transition PROTOCOL, not the full Observer struct.

The model's state (inside Arc + loom Mutex):
```rust
struct ModelObserver {
    state: PrimaryState,
    suspended: bool,
}

#[derive(Clone, Copy, Debug, PartialEq)]
enum PrimaryState {
    Inert,
    Runnable,
    Blocked,
    Faulted,
}
```

Model transition methods on ModelObserver (replicate the exact logic from
src/observer.rs):

- `resume() -> Result<(), ()>`:
  Match state: Inert|Faulted -> Runnable, clear suspended. Runnable+suspended|Blocked+suspended -> clear suspended. Otherwise Err.

- `suspend()`: Set suspended = true (always succeeds).

- `block() -> Result<(), ()>`:
  Runnable -> Blocked. Otherwise Err.

- `unblock() -> Result<bool, ()>`:
  Blocked -> Runnable, return !suspended. Otherwise Err.

- `fault() -> Result<(), ()>`:
  Runnable -> Faulted. Otherwise Err.

Write these `#[test]` functions:

1. `loom_observer_resume_suspend_race`: Start Inert. Thread A calls resume()
   (lock). Thread B calls suspend() (lock). After both join, assert state is
   valid: either (Runnable, false) — resume then suspend had no effect because
   resume cleared it — or (Runnable, true) — suspend applied after resume. Both
   are valid. Never (Inert, true) or any corrupted state.

2. `loom_observer_unblock_suspend_race`: Start Blocked, suspended=false.
   Thread A calls unblock() (lock). Thread B calls suspend() (lock). After
   both join, assert: state is Runnable. If suspend ran after unblock,
   suspended=true. If suspend ran before unblock, unblock returns false
   (suspended was already set). Either way, state is Runnable — never Blocked
   after unblock has been called.

3. `loom_observer_fault_block_race`: Start Runnable. Thread A calls fault()
   (lock). Thread B calls block() (lock). Exactly one succeeds (both require
   Runnable). After both join, state is either Faulted or Blocked — never
   Runnable (one must have transitioned) and never an error state.

4. `loom_observer_full_lifecycle`: Start Inert. Thread A: resume() then block().
   Thread B: after a yield, unblock() then suspend(). Verify the final state
   is valid per the state machine rules. Tests a longer sequence of transitions
   under concurrent access.

5. `loom_observer_double_resume_rejected`: Start Runnable (not suspended).
   Two threads both call resume(). Both should get Err (resume from Runnable
   without suspension is invalid). State remains Runnable. Property: invalid
   transitions are rejected under concurrency.

Each test wrapped in `loom::model(|| { ... })`.
