The primary challenge is that proptest cannot directly generate `NonNull<Observer>` — Observers must be stack-allocated with stable addresses. The strategy is to generate PARAMETERS (profiles, operation sequences) and then construct concrete Observers from those parameters in the property body.

Strategies to create:
- `valid_profile()`: generates (r: u8, t: u8) where r + t <= 128 and r, t are each in 0..=128. Use `(0u8..=128u8).prop_flat_map(|r| (Just(r), 0u8..=(128 - r)))`.
- `observer_count()`: 1usize..=8 (keep small — each observer needs a stack slot)
- `tick_count()`: 10u32..=200 (number of on_preempt calls)

Property tests to write:

1. `prop_eevdf_eligible_first`: Generate 2..=6 profiles via `prop::collection::vec(valid_profile(), 2..=6)` and a tick_count in 1..=50. Create Observers on the stack (use a fixed-size array of 6 Observers). Enqueue all, run tick_count on_preempt cycles. At each pick_next call, access the scheduler's internal entries to verify: if any entry has VET <= global_virtual_time, then the picked Observer also has VET <= global_virtual_time.

   Since entries and global_virtual_time are not pub, use an indirect check: verify the property by examining the scheduler's behavior. After each on_preempt + pick_next, the scheduler should never skip an eligible Observer in favor of a non-eligible one. Test this by: after each pick_next, verify the picked observer is in the queue (contains() returns true).

   Simpler alternative: verify the structural property — pick_next never returns None when the queue is non-empty. This is a necessary (not sufficient) condition but is the testable surface without accessing private fields.

2. `prop_eevdf_fairness_equal_weight`: Generate count in 2..=4 and ticks in 40..=120. Create `count` Observers with identical default profiles. Enqueue all. Run `ticks` cycles of on_preempt + pick_next. Count how many times each Observer is picked. Assert each gets at least `ticks / (count * 3)` picks (lower bound: 33% of fair share — generous tolerance for EEVDF edge effects).

3. `prop_eevdf_no_starvation`: Generate count in 2..=4 and profiles via `prop::collection::vec(valid_profile(), count)`. Create Observers with those profiles. Enqueue all. Run 200 * count cycles of on_preempt + pick_next. Assert every Observer was picked at least once.

4. `prop_eevdf_enqueue_dequeue_consistency`: Generate a sequence of operations as `Vec<bool>` (length 2..30) where true = enqueue next Observer, false = dequeue most recent. Track expected count. After the sequence, assert queue_depth() == expected_count and contains() is correct for each Observer.

5. `prop_eevdf_pick_next_nonempty_always_some`: Generate count in 1..=6 and ticks in 1..=100. Enqueue count Observers. Run ticks on_preempt cycles. At each step, assert pick_next().is_some() (queue is never empty since we never dequeue).

6. `prop_eevdf_total_weight_tracks`: Generate a sequence of enqueue/dequeue operations (Vec<bool>, length 2..20). Track expected total_weight (sum of weights of currently-enqueued observers — weight is always 100 for test_default observers with compute_aggregate=100). After each operation, assert sched.total_weight == expected.

Place proptest! blocks after the existing tests, commented with `// ── PROP-04: EEVDF scheduler properties ──`.

Do NOT modify any existing tests or production code.
