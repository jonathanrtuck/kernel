Add proptest property tests to the existing `#[cfg(test)] mod tests` block in src/arena.rs. Add `use proptest::prelude::*;` at the top of the test module.

Design an operation-sequence strategy for modeling arbitrary alloc/free interleavings:

```rust
#[derive(Debug, Clone)]
enum ArenaOp {
    Alloc,
    Free(usize),  // index into live_ids vec
}
```

Create a strategy that generates a Vec<ArenaOp> of length 1..80, where Free(idx) indices are constrained to be valid (idx < number of live ids at that point in the sequence). Use `prop::collection::vec` with a custom strategy that tracks state.

A simpler alternative (preferred for robustness): generate a `Vec<bool>` where `true` = alloc and `false` = free-most-recent. This avoids index tracking complexity in the strategy itself.

Property tests to write:

1. `prop_arena_alloc_ids_unique`: Generate count in 1..50u32. Allocate `count` objects. Collect all ObjectIds. Assert they are all distinct (use a BTreeSet or sort+dedup and compare length).

2. `prop_arena_alloc_free_realloc`: Generate count in 1..20u32. Allocate `count` objects, free them all, then allocate `count` again. Assert all reallocations succeed.

3. `prop_arena_mixed_ops_no_overlap`: Generate a `Vec<bool>` (length 2..80) as the operation sequence. Maintain a `Vec<ObjectId>` of live ids. For each `true`, allocate and push id. For each `false`, if live_ids is non-empty, pop last id and free it. After each operation, assert all live ids are distinct (no overlap).

4. `prop_arena_alloc_get_roundtrip`: Generate count in 1..30u32 and a value offset in 0..1000u32. Allocate `count` objects, writing `offset + i` as the value. Then for each (id, expected_value), assert `arena.get(id).unwrap().value == expected_value`.

5. `prop_arena_free_then_get_none`: Generate count in 1..30u32 and a free_index in 0..count. Allocate count objects, free the one at free_index, assert get() returns None for the freed id and Some for all others.

6. `prop_arena_live_count_consistent`: Generate a `Vec<bool>` (length 2..60) as operation sequence. Track expected live count (increment on alloc, decrement on free). After the sequence, count how many ids return Some from get(). Assert actual == expected.

Use the existing `TestObject` and `make_arena` helpers already in the test module. Place proptest! blocks after the existing tests, clearly commented with `// ── PROP-02: Arena allocation invariants ──`.

Do NOT modify any existing tests or production code.

Important: The arena in test mode has limited capacity (backed by a fixed slab). If allocate() returns OutOfMemory, do not count it as a live allocation — just skip it in the property logic. Use `prop_assume!(count <= 200)` or handle OutOfMemory gracefully in the property body.
