    1. SYSREG.RS ASM OPTIONS AUDIT (SAFE-04): This is the highest-value audit task. sysreg.rs has ~15 inline asm blocks wrapping MRS/MSR/DSB/ISB instructions. For EACH:

       - Identify the instruction (mrs, msr, dsb, isb, etc.)
       - Check options() against CLAUDE.md policy:
         * `mrs MPIDR_EL1`: immutable, `nomem` OK
         * `mrs CNTFRQ_EL0`: immutable, `nomem` OK
         * `mrs CNTVCT_EL0`: volatile counter read, `nomem` questionable (it reads a changing value but does not access memory — ARM ARM says it is a system register read, not a memory access. However, reads from CNTVCT must be ordered relative to surrounding memory operations for timer correctness. Check if `nomem` is present and whether it should be.)
         * `msr DAIF, ...`: modifies interrupt masking, affects all subsequent instructions. NO `nomem`.
         * `msr TTBR0_EL1, ...`: modifies page tables. NO `nomem`.
         * `msr VBAR_EL1, ...`: modifies exception vector base. NO `nomem`.
         * `msr CNTV_CVAL_EL0, ...`: sets timer comparator. NO `nomem`.
         * `msr CNTV_CTL_EL0, ...`: controls timer enable/mask. NO `nomem`.
         * `dsb ishst` / `dsb ish` / `dsb sy`: barrier instructions. NO `nomem` (they exist to order memory).
         * `isb`: instruction synchronization barrier. NO `nomem`.
       - For each asm block, add or verify a comment: `// ARM ARM: <instruction> — <side effects> — <nomem justification or prohibition>`
       - If `nomem` is present but should not be, REMOVE IT and add a comment explaining why.

    2. SPECULATION.RS (SAFE-04, SAFE-05): 2 unsafe blocks:
       - The `SB` (Speculation Barrier) instruction itself: verify options. SB is a barrier — `nomem` is debatable (it does not access memory, but its purpose is to prevent speculative memory access). Check ARM ARM FEAT_SB for guidance.
       - Verify the speculation_barrier() function is correctly gated on cfg(any(target_os = "none", test)).

    3. CPU.RS (SAFE-04): 2 unsafe blocks:
       - MPIDR_EL1 read: verify `nomem` is correct (MPIDR is truly immutable per ARM ARM D13.2.88).
       - PSCI CPU_ON: verify the HVC call does not use `nomem` (HVC is a hypervisor call, has side effects).

    4. MMIO.RS (SAFE-04): 3 unsafe blocks:
       - Volatile read/write: verify `core::ptr::read_volatile` / `write_volatile` usage.
       - These should NOT have asm options issues (they use Rust volatile, not inline asm). Verify SAFETY comments are present and accurate.

    5. GIC.RS (SAFE-04): 1 unsafe block:
       - Verify it is an MMIO access or system register access with correct SAFETY comment.

    6. PSCI.RS (SAFE-04): 2 unsafe blocks:
       - HVC #0 calls: verify NO `nomem` (HVC transfers control to the hypervisor, has arbitrary side effects).
       - Verify options include `noreturn` for SYSTEM_OFF/SYSTEM_RESET if applicable.

    7. DTB.RS (SAFE-01, SAFE-02): 2 unsafe blocks:
       - Parsing untrusted firmware data. Verify SAFETY comments document the trust boundary.
       - Verify bounds checks happen BEFORE the unsafe pointer dereference.
