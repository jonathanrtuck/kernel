<objective>
Audit every unsafe block in the memory subsystem: mapping.rs (14 unsafe, 5 gap), mmu.rs (5 unsafe, inline asm), boot.rs (19 unsafe, 1 gap), and slab.rs (16 unsafe, 2 gap).

Purpose: The memory subsystem converts physical addresses to pointers, programs page tables, and manages slab allocations. Bugs here cause silent memory corruption, page table corruption, or TLB coherency issues. The asm options() audit is especially critical for mmu.rs — wrong nomem can cause LLVM to reorder memory accesses past TLB operations.

Output: All four files have zero SAFETY comment gaps, asm options are verified against ARM ARM, and speculation barriers are checked.
</objective>

    Part A — mapping.rs (14 unsafe blocks, 5 gap):

    1. SAFETY GAP CLOSURE (SAFE-01): Find the 5 unsafe blocks missing SAFETY comments. Known candidates:
       - `pa_to_table`: inner `unsafe` may lack separate comment from the outer `unsafe fn`
       - `map_space_in_observer`: multiple `unsafe` calls to `pa_to_table` — each needs its own SAFETY comment
       - `unmap_space_from_observer`: similar pattern
       - `populate_l3_at_pa`: may have gap
       For each gap, add a `// SAFETY:` comment explaining: PA validity, exclusive access, linear map requirement.

    2. PRECONDITION VERIFICATION (SAFE-02): For every `pa_to_table` call:
       - Verify the PA source is either from the L1 table entry, a fresh SpaceManager allocation, or an Observer's page_table_root
       - Verify "exclusive access" claim — mapping.rs holds &mut SpaceManager (through the lock), ensuring no concurrent page table modifications
       - For `wire_space_mapping` and `unwire_space_mapping` safe wrappers: verify they acquire the SpaceManager lock before calling into the unsafe functions

    3. ALIASING CHECK (SAFE-03): `pa_to_table` returns `&'static mut [u64; ENTRIES_PER_TABLE]`. Verify:
       - No two calls to `pa_to_table` with the same PA exist within the same scope
       - The L1 and L2 tables obtained in `map_space_in_observer` always have distinct PAs

    Part B — mmu.rs (5 unsafe blocks):

    4. ASM OPTIONS AUDIT (SAFE-04): For every inline asm block in mmu.rs:
       - Read the ARM ARM entry for the instruction
       - Verify `nomem` is only used on mrs of truly immutable registers
       - Verify `nostack` is only used when the instruction does not touch the stack
       - Verify `preserves_flags` is only used when NZCV is not modified
       - For TLB invalidation instructions (`TLBI`): verify NO `nomem` (TLBI affects memory-mapped TLB state)
       - For DSB/ISB barriers: verify NO `nomem`
       - For MSR instructions (TTBR0_EL1, TTBR1_EL1, SCTLR_EL1): verify NO `nomem`
       If any asm options are incorrect, fix them and add a comment citing the ARM ARM justification.

    5. SPECULATION BARRIERS (SAFE-05): Check whether any user-provided index is used to compute a page table entry address. If so, verify a speculation barrier is present between the bounds check and the dereference.

    Do NOT change functional logic. Fix SAFETY comments and asm options only. Document soundness bugs as open-bug.

    4. SAFETY GAP CLOSURE (SAFE-01): Find the 2 missing SAFETY comments. Known candidates in the bare-metal SlabStore:
       - `allocate()` has multiple unsafe blocks (freelist read, write_bytes, cast to &mut T)
       - `insert()` has similar pattern
       - `slot_ptr()` has a SAFETY comment on the debug_assert but may lack one on the computed address

    5. PRECONDITION VERIFICATION (SAFE-02): For slab.rs:

       - `allocate` freelist read: verify the free slot's first 4 bytes are a valid u32 next-pointer
       - `get`/`get_mut`: verify bitmap-checked slots contain valid T values
       - `free`: verify the freed slot's next-pointer write does not corrupt adjacent slots
       - Test build `allocate`: verify `MaybeUninit::zeroed().assume_init()` — the SAFETY comment warns about NonNull. Confirm this is documented and callers of types with NonNull use `insert()` instead.

    6. ALIASING CHECK (SAFE-03): `for_each_mut` creates `&mut T` references in a loop. Verify:

       - The callback `f` does not call back into the same SlabStore (which would create aliased &mut)
